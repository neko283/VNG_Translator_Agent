# Artemis 解包与汉化流程

适用顺序为“引擎与包格式确认 → 逐包提取 → 更新合并验证 → 文本与字体小样 → 全量提取与术语入库 → Agent 翻译 → 回填封包 → 实机验收”。[公共流程](../../Translation_Workflow/通用实施流程.md)规定记录与验收方式，本页描述 Artemis 的适配点。解包、封包参数与限制见 [Artemis 工具使用说明](README.md)，以下本地工具路径均以工具包根目录为基准。

## 1. 识别资源与记录编码

检查主程序中的引擎／版本标识、每个包的实际 magic、资源目录和脚本后缀，不能仅凭 `.pfs` 扩展名认定 PF8。本地工具仅支持 `pf8`；PF2、PF6 或变体需另加经验证的工具。

对每个包调用 `python3 Game_Engine_Tools/Artemis/tools/pf8.py list`。先验证路径编码，保持严格解码，不用替换字符掩盖错误。包内路径与正文编码独立记录。每个带独立头部和索引的 `.pfs.NNN` 单独处理，不拼接为一个 ZIP 分卷。

## 2. 分别解包与建立有效资源

调用 `extract`，分别输出到游戏实施目录的 `work/unpacked/<包标识>/`，manifest 放到 `work/manifest/`。优先提取配置、剧情、必要字体；不默认解出音频和图片。

按 manifest 比较同路径文件，形成更新来源表。候选覆盖顺序要通过配置和运行实验确认，不能只按包编号大小断言；保留原包独立结果，再建立 `work/effective/`。

小样要求：独立读取器能够得到一致的明文；原包哈希不变；提取文件数符合清单；路径未乱码；已知脚本能按严格编码正确读取。任何未加密例外必须有正文证据，再显式使用 `--plain-pattern`。

## 3. 剧情转换与选择项识别

Artemis 不同作品可能使用 `.txt`、`.ast`、`.asb`、`.iet`、Lua 等。本包不附带任何游戏的脚本或专属解析器；先调查当前游戏语法，不能直接套用其他作品的解析规则。

VNTextPatch 可作为候选：

```text
VNTextPatch.exe extractlocal scenario_input translation_json --format=artemistxt
VNTextPatch.exe insertlocal scenario_input translation_json scenario_output --format=artemistxt
```

其 [ArtemisTxtScript 实现](https://github.com/arcusmaximus/VNTranslationTools/blob/main/VNTextPatch.Shared/Scripts/Artemis/ArtemisTxtScript.cs)对命令属性主要处理 `name` 与 `sel_text`，仍需逐作品核对自定义宏、空行分段、文件末尾消息和换行规则。输入目录只放匹配格式的剧情文件。

定位字段、原文、正文编码和控制标记独立保存。不得把 Agent 导出的 Message-JSON 直接当成 VNTextPatch 的回填格式；应保留原提取结果，由转换层仅更新对应译文字段。

选择项需沿调用链确认：脚本参数 → 系统函数 → 字体／文本绘制或图片加载。无论是文本叠加还是图片选项，默认都保留原文，不进入翻译输入；label、file、exp、cond 等逻辑字段也保持原值。候选提取器若导出 `sel_text`，转换层必须排除并验证回填未修改。不能将某个游戏的结论推广到所有 Artemis 作品。

## 4. 编码与字体小样

先做不翻译的往返，再验证中文对白/旁白、标点、历史记录与原文姓名/选项的兼容性。使用开头到首个选项前的小样，等待人工确认字体和格式后再全量翻译。不能把 CP932 脚本直接存成 GBK 就认为引擎会读取中文。根据实际结果选择可用编码、文字转换或字符映射，并验证原程序的渲染路径。

旧作 IET／RFT 与新作字体表可能有不同配置。Artemis [官方功能说明](https://www.ies-net.com/?page_id=24)提及 TTF／OTF 与预先图像化字体，但具体版本仍需检查。TTF 改名 `.rft` 不构成格式转换。

检查正文、选项、历史记录和存档摘要是否使用不同字体；排版按实际像素宽度和中文标点处理。共享字体改变后验证原有日文界面兼容性，但不扩大文案翻译范围。

[Artemis Legacy 字体适配资料](https://github.com/SuQiandYing/SimpleFontHook/blob/main/SimpleFontHook/hooks/internal/engines/artemis_legacy/README.md)与 [SJIS tunneling 思路](https://github.com/arcusmaximus/VNTranslationTools#shift-jis-extension)可作为后续研究参考，尚未证明其直接兼容每个游戏。

## 5. 全量术语提取与翻译

使用 [LinguaGacha_Agent 公共工作流](../../Translation_Workflow/LinguaGacha_Agent工作流.md)。无需修改 Agent；游戏侧负责输入转换、上下文、稳定映射、结果检查与脚本恢复。先通过小样，再冻结全量输入。按 [术语流程](../../Translation_Workflow/术语提取流程.md) 阅读指定网页及全部语料，提取候选、核对来源/语境并写入正式 glossary，完成 terms 后再批量翻译。网页读取由宿主完成，不能假定 CLI 会自动抓取。

## 6. 回封与补丁

本地 `pf8.py` 0.2.0 已有 pack。正式构建从本轮原版解包及清单开始，遵循 [独立构建与原版安装契约](../../Translation_Workflow/正式构建与安装流程.md)，不依赖任何测试包或旧备份。开发或适配时必须满足：复用已有资源的原始名称字节；新增资源尽量使用 ASCII 路径；显式保持目录分隔符；以编码后字节长度重算索引、偏移、大小和索引 SHA-1；依据新索引重新处理正文。不能拼接旧索引密文代替回封。

按稳定顺序构建，重新解包并逐项比较资源内容。包整体哈希可因布局变化而不同，但明文与路径必须符合预期。补丁根目录直接使用实际包内路径，不能多包工作目录一层。

逐游戏验证新增编号包、散文件或替换分包的加载方式。新增包名与编号没有跨作品保证；替换时需保留更新包已有修改。优先提供只含必要修改的增量补丁，必要时本地重建／差分安装并备份基线。

## 7. 验收与归档

共通线、角色线、分支、语音、历史记录、自动／跳过、存读档、回想重播及安装卸载均需记录。区分静态脚本证据、工具往返检查和真正游戏运行结果。具体命令与证据放入 `<user_work_root>/release/<game_id>/实施日志.md` 和 `evidence/`，最终状态写入 `结果与验收.md`。

## 当前分发边界

PF8 工具和合成测试随包提供；游戏运行、字体和安装验收需在当前游戏独立完成。历史游戏的实测记录、译文、字体映射和补丁均未随包分发，不能作为新游戏已经验证的依据。
