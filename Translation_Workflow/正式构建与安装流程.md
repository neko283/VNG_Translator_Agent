# 从游戏本体开始的正式构建与安装

目标是：制作端可以从新工作区和原始游戏资源重建补丁；玩家端仅有兼容的游戏本体时，复制正式补丁即可首次安装。旧测试补丁、旧工作目录、旧 manifest、旧 `.lg` 和旧备份均不是必需输入。

## 1. 两种环境与输入

| 环境 | 必需输入 | 不应依赖 |
| --- | --- | --- |
| 制作端 | 支持版本的原游戏、已登记的工具/适配器、独立取得并校验的字体及许可、正式术语和翻译产物 | 测试 ZIP/payload、旧解包目录、开场 `.lg`、旧构建报告、测试派生字体、旧安装备份 |
| Windows 安装端 | 可运行且哈希匹配的游戏本体、本次正式发布包及系统自带安装脚本运行环境 | 测试补丁、制作端工作区、Node/Python、用户全局安装的中文字体、测试版 backup |

“仅有游戏本体”指完整可运行的兼容版本，包括该版本需要的资源、视频及运行组件，不等于只有主程序。游戏已有的官方更新资源属于版本基线；基线不匹配时不能偷偷要求先装汉化测试版。

可以复用已验证的算法和源代码；须移除其中的旧任务 ID、绝对机器路径、开场行号、测试目录依赖和读取旧产物的逻辑。旧小样只供设计参考，不作为正式构建链的一环。当前旧脚本如未完成这一改造，必须标记为“测试专用”。

## 2. 制作端完整流程

1. 接收显式配置的游戏目录、独立工作目录、工具与字体来源；先只读校验，记录主程序及相关资源哈希。所有输出进入新工作区。
2. 逐包解出必要资源，生成本轮 manifest 和更新来源清单，建立本轮有效资源视图。
3. 全量解析剧情并做原文往返检查，冻结输入、定位清单和上下文；不得拼接旧小样输出补齐开场。
4. 执行 [术语提取](术语提取流程.md)，新建正式 `.lg` 并入库，再执行全量翻译、审校和导出检查。
5. 从本轮最终译文、原脚本及全量字符集计算编码与字体方案；从固定版本/哈希的原字体重新生成派生字体，独立附许可。
6. 用本轮原模板、定位清单、正式导出结果回填。构建替换资源或经验证的差分补丁，不从测试补丁取资源作为底包。
7. 重新解包比对修改与未修改资源，检查控制结构、路径、字体引用和翻译覆盖。记录构建输入、工具版本、字体、术语/译文摘要和输出哈希。
8. 独立制作安装脚本与使用说明。正式 manifest 由支持的原版基线和本次正式输出生成，禁止为构建正式包而读取 `upgrade_from_v1` 等测试元数据。

建议每次全量实施建立 `<游戏实施目录>/work/runs/<批次>/`，保存 manifest、unpacked、effective、terms、translation、font、patch_files、build、qa。续做同一批次时恢复其 `.lg`；换原文版本则新建批次。已发布构建应能用冻结的正式翻译产物复建，无需再次请求模型生成相同文字。

## 3. 字体容量与存档

字体小样通过只证明对应字符集和显示场景。正式版必须重新统计整部游戏的中文、标点、姓名、选择项、注音、历史和存档摘要字符，不把小样映射表直接扩充后默认为安全。

采用占位字形映射时，排除所有原文、资源键、译文及会经过该字体的其他可见文字中的字符，检查编码往返一致、映射唯一性、容量和冲突。如果可用位置不足，停止该构建并调整有实测依据的方案，不能截断字符、复用冲突位置或退回问号。

一个正式版本冻结一份全局映射；后续修订尽量保留已有分配。新增或改映射须检查旧正式存档中的文本，必要时使用新存档命名空间或明确可验证的迁移方式。正式版不导入测试存档，也不以测试存档为启动条件。

## 4. 原版首次安装契约

安装包至少包括正式资源或本地差分重建工具、manifest、安装/还原脚本、说明和字体许可。玩家无需运行 Agent、联网提术语或重新生成字体。

安装顺序：

1. 确认游戏已退出、目录正确且可写；核对支持的游戏主程序/资源版本、补丁 payload 完整性、所需文件存在。
2. 全部预检通过后，首次创建属于正式版本的备份目录，从当前已确认的原版备份待替换文件并校验。预先不存在任何 backup 也必须能够正常安装。
3. 写入正式资源并复核哈希；写入失败恢复已验证的原文件。记录安装完成标记与版本。
4. 重复安装同一正式版本应识别已安装状态，并核验原版备份；未知改动不得当作原版备份或强行覆盖。
5. 还原前检查本次正式备份和当前文件，按原版哈希恢复。保留用户存档和备份，不删除其他文件。

无需自动升级测试版。发现旧测试文件时可明确提示使用旧版还原或换用干净游戏副本，但这不能成为原版用户的安装前置要求。未来正式版升级支持须单独登记兼容矩阵，不混入此次原版首次安装路径。

## 5. 证明独立性的验收

| 检查 | 通过标准 |
| --- | --- |
| 制作端重建 | 新工作区，仅可访问原版游戏、声明的工具/字体、正式术语翻译数据；不提供旧测试目录，仍能完成全部构建 |
| 依赖清单 | 构建输入和读取路径记录无测试包、旧构建 manifest、测试字体或旧备份依赖；仅搜索字符串不足以代替隔离重建 |
| Windows 原版首次安装 | 在从未装测试补丁、无任何 backup 的支持版本副本上安装成功 |
| 失败与还原 | 错误版本/损坏 payload 在修改前拒绝；写入失败可恢复；正式版卸载后原包哈希吻合 |
| 重复安装 | 已安装正式版被正确识别，不覆盖唯一原始备份 |
| 字体与功能 | 正式全字符集、剧情分支、历史、存档摘要、保存重启读档及原日文界面经过测试 |

本文件是实施和验收契约；是否已完成脚本开发、隔离重建和实机测试，以各游戏结果报告为准。
