# 游戏实施方案

状态：未实施。替换为游戏名称，填写以下内容后开始工作。

## 目标与范围

游戏原目录、发行版、引擎版本、源语言与目标语言；包含哪些剧情文本、明确排除哪些内容。文本和图片选择项都默认保留原文。

## 资源与证据

列出资源包、格式、路径编码、正文编码、更新覆盖关系、脚本类型、字体与渲染路径。每项标为已验证或待确认，并链接 `evidence/` 中证据。

## 工具与工作区

引用引擎通用工具及版本，注明已实现和待适配功能。工作数据统一进入 `work/`；新增游戏专属适配时放 `adapters/`，记录原因，避免修改公共工具来硬编码游戏。

## 实施步骤

按 公共流程（工具包内 `Translation_Workflow/通用实施流程.md`） 执行：基线 → 独立解包 → 有效资源 → 小样 → 文本提取 → 术语提取与入库（工具包内 `Translation_Workflow/术语提取流程.md`） → Agent 翻译与审校（工具包内 `Translation_Workflow/LinguaGacha_Agent工作流.md`） → 独立回填构建 → 原版首次安装/还原 → 实机验收。

这里只补充游戏具体命令、输入输出路径、语言设置和阶段通过条件。翻译开始前记录 `LG_WORK`、`.lg` 路径；创建任务后再记录实际任务 ID。

## 待确认项与验收

中文编码与字体、引擎加载优先级、补丁命名、长句布局、存档兼容、路线覆盖、安装与卸载。不能将候选配置写成已经验证的事实。

## 术语来源与独立安装

列出用户指定的官方和辅助网址，记录访问状态、候选、出处、语境与冲突。确认正式 glossary 生效后再翻译；未执行抽取时不将术语表标为完成。

按 正式构建与安装（工具包内 `Translation_Workflow/正式构建与安装流程.md`） 明确支持的原版、工具/字体依赖及独立工作区。正式链路不能读取测试包、旧工作区或旧 backup；记录隔离重建、没有旧备份的首次安装、失败回滚和还原验收结果。
