## 与方案细节的落实方式

- 使用 `linguagacha_agent.task.* / batch.* / receipt.* / review.* / translated.* / terms.* / export.* / pause.*` 元数据；协议版本为 1。没有新建业务数据库或 Item 状态。
- 恢复以当前 `.lg` 为准，任务的阶段和计数从真实条目重新推导。已保存的术语调查与候选在 `resume/next/query` 中返回，不依赖旧聊天上下文。
- 批次尝试 ID 即 `next` 返回的 `attempt`。回执摘要绑定原提交内容，不绑定工作目录绝对路径。回执同时列出逐项接受/变更结果、成功保存的审校 ID 和涉及的规则身份。批次保存译前输入快照，避免并发修改其他条目后临时资源编号发生漂移。
- 事务服务在 `BEGIN IMMEDIATE` 内校验规则依据、原对象指纹并保存回执。CLI 命令通过 SQLite 写事务串行化；没有另建进程锁文件，因此进程意外退出不留下需要人工删除的锁。
- 原 SDK 的连接装配替换为同步 SQLite 连接适配，领域访问类和业务写入服务保留。数据库回调必须同步，避免把异步模型调用放进数据库锁。
- 工作目录可由宿主自行创建，用于草稿和输出报告；CLI 不要求它存在，也不从中读取唯一进度。
- 审校修订使用原人工补丁；新增 `translations` 协议明确区分模型输出与已经恢复的最终文本，避免替换和恢复执行两次。
- 规则开关通过 `configure` 调用原规则写入服务。变更后旧批次失效，已有译文保留，依赖旧依据的审校结论需重新确认。
- 导出使用原写出器。零条目 TXT/JSON 没有可写分组，因此不生成文件；CLI 用 `zero_item_assets` 明确报告，没有擅自补一个新写回规则。
- 初次导入默认 `ALL → ZH`，用户可显式选源语言；这是独立 CLI 的入口默认值，不改变原语言过滤算法。已有工程沿用其语言配置。

- 23 项集成测试：三格式写回、空译文、同文译文、重复项、部分拒绝、丢失回复、工程移动、事务回滚、术语变更、审校失效、外部改动、混合格式子集、源资产变化、未知迁移拒绝、实际子进程退出、替换与保护、错误重试、UTF-16、迁移备份、并发进程、便携构建、路径冲突、原 changes 目录提交、术语调查恢复和固定译前快照。
- 复制的原工程迁移与 `ProjectDatabaseAccess` 执行往返后，命名空间元数据、未知 Item 字段及无关表仍保留。
- 便携测试只复制 `bin/`、`dist/` 和运行依赖，执行 doctor、导入、建任务、翻译提交及导出；不携带 `upstream/`，不读取原项目源码。
- 构建输入、TypeScript 依赖、文档及技能链接的目录边界检查。
- 共享技能与两个宿主入口的名称、frontmatter 和正文完整性检查。

## 维护边界

- 原格式与原模型代码在 `upstream/`，本项目 CLI、调度和恢复在 `src/`。来源摘要与必要改动见 [UPSTREAM.md](UPSTREAM.md)。
- 任务快照当前按工程读取，并按批次返回；大工程的分页和资产摘要缓存还未优化。
- 首版保留回执和检查点，不自动清理恢复记录。大量长期任务会增加 `.lg` 元数据体积。
- 输出中断可能留下部分文件；恢复会根据摘要重新要求导出，不承诺多个输出文件具备单个 SQLite 事务那样的原子性。
- 不提供其他格式、跨格式转换、桌面功能、额外模型执行器或网站抓取服务。
